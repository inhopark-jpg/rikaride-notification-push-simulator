# 리카라이드 공지 발행 시뮬레이터

어드민에서 공지의 "발행 대상 설정"을 바꾸면 이용자 앱의 어느 화면에 어떻게 표출되는지 보여주는 웹 프로토타입입니다. 백엔드 없이 브라우저에서 동작합니다.

## 실행 방법

Node.js 20 이상이 필요합니다.

```bash
npm install
npm run dev     # http://localhost:5173
npm test        # 판정 로직 단위 테스트
npm run build   # 타입 체크 + 프로덕션 빌드
```

주소에 `?preset=<id>`를 붙이면 예시 시나리오(`src/domain/presets.ts`)로 열립니다. 이때는 자동 저장을 읽지도 쓰지도 않습니다.
(`app-korea`, `incheon-bus`, `all-future`, `popup-overlap`, `no-city`)

## 자동 저장

`npm run dev`로 실행하면 무엇이든 바꾼 뒤 0.5초 뒤 `presets/_autosave.json`에 저장되고, 페이지를 다시 열면 그 상태로 복원됩니다. 가상 현재 시각도 저장되므로 저장 당시의 결과가 그대로 재현됩니다.

## Netlify 등 정적 호스팅에 올리기

`npm run build`로 만든 `dist/` 폴더를 Netlify Drop에 올리거나, 저장소 연결 시 Build command `npm run build`, Publish directory `dist`로 설정합니다. 올린 사이트에는 자동 저장이 없어서 빈 상태로 시작하고, 새로고침하면 초기화됩니다.

## 화면 구성

| 열 | 내용 |
|---|---|
| 1. 서비스 Configuration | 국가 → 도시 → 제공 서비스 매핑. 직접 편집(추가 시 무작위 이름 제안) |
| 2. 어드민 공지 발행 | 공지 유형, 게시 기간, 제목/본문, 중요 공지, scope 선택. 작성 중인 공지는 발행 전에도 열 4에 바로 반영되고, "발행"을 누르면 발행된 공지 목록에 추가됨. 발행 목록에서 수정/삭제 |
| 3. 사용자 앱 Configuration | 가상 현재 시각, 앱 국가, 선택한 도시, 예약/이용 중인 서비스(도시·서비스·이용일) |
| 4. 이용자 앱 표출 결과 | 휴대폰 화면 목업: Guide 탭, Ride 탭, 알림 센터, 서비스별 랜딩(지도 위 "○○ 보기"로 도시 전환), 팝업. 공지 외 영역은 스켈레톤. 공지 카드에 마우스를 올리면 표출 이유가 보임 |

각 열 헤더의 "초기화"는 그 열만 되돌립니다. 열 1은 서비스 구성, 열 2는 발행된 공지와 작성 중인 양식, 열 3은 앱 설정·예약·현재 시각, 열 4는 앱 안에서 바뀐 상태(읽음, 닫은 카드, 팝업 닫기/다시 보지 않기, 지도 위치)를 비웁니다.

## 판정 규칙 요약표

판정은 위에서 아래로 진행합니다. 구현은 [src/domain/visibility.ts](src/domain/visibility.ts)의 `evaluateNotice`입니다.

| 단계 | 앱 공지 | 이동 서비스 공지 | 미충족 시 표시되는 이유 |
|---|---|---|---|
| 1. 게시 기간 | `시작 ≤ 현재 ≤ 종료` | 동일 | 게시 기간 시작 전 / 게시 기간 종료 |
| 2. 국가 | 사용자 앱 국가가 국가 scope에 포함 | 동일 | 사용자 앱 국가가 국가 scope에 없음 |
| 3. 도시 | 보지 않음 (도시 0개여도 노출) | 사용자가 선택한 도시 중 하나 이상이 도시 scope에 포함 | 사용자가 도시를 선택하지 않음 / 선택한 도시가 도시 scope에 없음 |
| 4. 서비스 | 보지 않음 | 3에서 남은 도시 중 서비스 scope의 서비스를 실제 제공하는 도시가 있음 (도시별로 판정) | 선택한 도시에 해당 서비스 미제공 |
| 5. 노출 위치 | Guide 탭 + 알림 센터 | "서비스 전체" 공지면 Ride 탭, 아니면 4에서 남은 서비스의 랜딩마다 각각. 단, 중요 공지는 서비스 전체가 아니어도 Ride 탭에도 표시. 알림 센터에는 1건 | |
| 6. 팝업 | 중요 공지 + 1~2 충족 | 중요 공지 + 1~2 충족 + 예약/이용 조건 (아래) | 팝업 패널의 체크리스트 |

### scope 포함 판정

각 scope(국가/도시/서비스)는 발행 시점의 스냅샷 목록과 두 플래그를 따로 저장합니다.

| "전체 선택" | "차후 추가 포함" | 포함되는 항목 |
|---|---|---|
| 꺼짐 | 해당 없음 | 직접 선택한 항목 |
| 켜짐 | 꺼짐 | 발행 시점에 있던 항목 전체 (이후 추가된 항목은 제외) |
| 켜짐 | 켜짐 | 발행 시점 항목 + 이후 추가되는 항목 모두 |

- 계층마다 독립적으로 판정합니다. 예를 들어 국가가 "전체 + 차후 포함"이어도, 신규 국가의 도시는 도시 scope도 "차후 포함"이어야 들어갑니다.
- 도시 옵션은 선택한 국가에 속한 도시로, 서비스 옵션은 선택한 도시에서 제공되는 서비스로 좁혀집니다.

### "서비스 전체" 공지 (Ride 탭 노출)

발행 시점에 확정하지 않고, 판정할 때마다 다시 계산합니다 (`isServiceWide`).

**서비스 scope가 "공지 대상 도시들에서 현재 제공되는 서비스"를 전부 포함하면 서비스 전체**입니다.

| 발행 설정 | 발행 직후 | 대상 도시에 신규 서비스가 추가된 뒤 |
|---|---|---|
| 서비스 전체 선택 + 차후 포함 | Ride 탭 | Ride 탭 (신규 서비스도 scope에 포함) |
| 서비스 전체 선택, 차후 미포함 | Ride 탭 | 발행 시점 서비스 각각의 랜딩 (더 이상 전체가 아님. 신규 서비스 랜딩에는 없음) |
| 선택 가능한 서비스를 전부 개별 선택 | Ride 탭 | 선택한 서비스 각각의 랜딩 |
| 일부 서비스만 선택 | 선택한 서비스 각각의 랜딩 | 동일 |

- 공지 대상 도시에서 제공하지 않는 서비스가 추가된 경우에는 영향이 없습니다.
- "서비스 전체" 공지는 Ride 탭에만 보이고 개별 서비스 랜딩에는 중복 표시하지 않습니다.
- **중요 공지 예외**: 특정 서비스만 지정한 이동 서비스 공지라도 중요 공지면 Ride 탭에도 표시합니다. 서비스 랜딩 표시는 그대로 유지됩니다. 단, 1~4단계를 통과해 사용자에게 유효한 공지일 때만이며, 팝업만 뜨는 경우(도시 미선택 등)에는 Ride 탭에 나오지 않습니다.

### 중요 공지 팝업

| 조건 | 앱 공지 | 이동 서비스 공지 |
|---|---|---|
| 게시 기간 내 | 필요 | 필요 |
| 앱 국가가 국가 scope에 포함 | 필요 | 필요 |
| 사용자가 선택한 도시 | 보지 않음 | **보지 않음** |
| 대상 서비스를 예약했거나 이용 중 | 해당 없음 | 필요 (예약의 서비스가 서비스 scope에 포함) |
| 예약/이용 도시가 도시 scope에 포함 | 해당 없음 | 필요 (예약의 도시가 도시 scope에 포함) |
| 예약/이용일이 게시 기간과 겹침 | 해당 없음 | 필요 (예약/이용은 하루 단위, 이용일 00:00~23:59) |
| "다시 보지 않기"를 누르지 않음 | 필요 | 필요 |

- 조건을 충족하는 동안 앱을 실행할 때마다 뜨고, "다시 보지 않기"를 누른 공지만 빠집니다.
- 서비스·도시·기간 세 조건은 같은 예약 1건에서 모두 맞아야 합니다. 예: 인천 호출버스 중요 공지는 서울 호출버스 예약자에게 뜨지 않습니다.
- 이동 서비스 공지의 팝업은 사용자가 앱에서 "선택한 도시"와는 무관하고 예약 건의 도시만 봅니다. 그래서 알림 센터에는 없는데 팝업만 뜨는 경우가 있습니다 (예시 `?preset=no-city`).

### Ride 탭 서비스 CTA 배치

Figma ".unpub_service-cta-layout"(node `12806:169247`) 규칙을 따릅니다 ([src/domain/ctaLayout.ts](src/domain/ctaLayout.ts)).

- 6열 그리드에서 카드는 full / half / third 너비. 위에서부터 full 줄 → half 줄(2개씩) → third 줄(3개씩).
- 우선순위: third가 많은 배치 → half가 많은 배치 → 전부 full. 서비스 이름이 그 너비에 한 줄로 들어가는 가장 앞선 배치를 고릅니다.
- 예: 호출버스·전담 기사·공항 셔틀은 3열 한 줄, 광역 호출버스가 섞이면 full 1개 + half 2개.

### 공지 카드 닫기

알림 센터 외 화면(Guide·Ride·랜딩)의 공지 카드에는 x 버튼이 있어 그 화면에서만 숨길 수 있습니다. 알림 센터에는 그대로 남습니다. 열 4 상단의 "닫은 공지 복원"으로 되돌립니다.

### 서비스 랜딩

같은 서비스 랜딩이라도 지도에 보이는 도시에 따라 공지가 다릅니다. 프로토타입에서는 랜딩 화면 위의 "지도 위치(가상)"로 사용자가 선택한 도시 중 해당 서비스를 제공하는 도시를 골라 봅니다. 공지는 그 도시가 공지 대상이고, 그 도시에서 해당 서비스를 제공할 때만 보입니다.

### 알림 센터

- 배지(중요·도시·서비스)는 알림 목록에서만 표시합니다. Guide 탭, Ride 탭, 랜딩, 팝업의 공지에는 배지를 붙이지 않습니다.

Figma "공지 표출 규칙" 섹션(node `17588:82306`)의 규칙과 list item 디자인을 따릅니다.

- 5단계까지 통과한 공지만 표시합니다. 게시 기간이 지난 공지는 남지 않습니다.
- 중요 공지를 최상단에 두고 "중요" 배지와 빨간 배경으로 강조합니다.
- 도시 배지는 발행 대상 도시 중 사용자가 선택했고, 공지 대상 서비스를 실제로 제공하는 도시만 가나다순으로 표시합니다. 예: 인천·서울 대상 공항 셔틀 공지는 공항 셔틀이 없는 서울 배지를 붙이지 않습니다.
- 서비스 배지는 도시 배지 뒤에 가나다순으로 표시합니다. "서비스 전체" 공지는 서비스 배지가 없습니다.
- 앱 공지에는 도시/서비스 배지가 없습니다.
- 읽음 상태는 국가나 도시 설정을 바꿔도 유지됩니다.

## 확인이 필요한 가정

아래는 확정 답변 없이 구현자가 정한 부분입니다. 개발팀과 대조할 때 먼저 확인하세요.

| # | 가정 | 바꾸려면 |
|---|---|---|
| 1 | 이동 서비스 중요 공지 팝업도 앱 국가는 국가 scope에 있어야 한다 (선택한 도시만 무시) | `judgePopup` |
| 2 | "기간 겹침"은 이용일과 게시 기간의 겹침만 본다. 이용일이 지난 예약도 게시 기간과 겹쳤다면 게시 기간 중에는 팝업이 뜬다 | `judgePopup` |
| 3 | 정렬은 중요 공지 우선, 그다음 게시 시작 일시 최신순 | `compareNotices` |
| 4 | 알림 센터의 서비스 배지는 공지에 지정된 서비스 중 사용자 도시에서 실제 제공되는 것만 표시한다 | `evaluateNotice` |
| 5 | "서비스 전체" 공지는 Ride 탭에만 표시한다 | `evaluateNotice` |
| 6 | list item의 날짜는 게시 시작 일시다 | `NotificationListItem` |
| 7 | 공지를 수정해 저장하면 scope 스냅샷을 현재 구성 기준으로 다시 만든다 | `buildNotice` |
